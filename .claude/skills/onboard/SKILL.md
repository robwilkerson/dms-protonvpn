# Onboard

Get set up to develop this plugin. Generated by `/project init`.

## Instructions

1. **Orientation** — Point the reader at these, in order, and say briefly what each covers:

   - **`SESSION_CONTEXT.md`** — the whole design so far: target UI, hard
     constraints, verified data sources, the server-selection algorithm, and the
     open questions. Start here; nothing else makes sense without it.
   - **`CLAUDE.md`** — the constraints in short form, the dev loop, and the
     related-repo triggers.
   - **`~/.config/DankMaterialShell/plugins/dankscale/`** — the reference
     implementation. `Tailscale.qml` for the bar-pill-plus-popout shape,
     `components/TailscaleLogo.qml` for hand-drawing a themed mark.

2. **Prerequisites** — Check each and report what's missing:

   - **DankMaterialShell `>= 1.4.0`** — `dms ipc call plugins list` should answer.
   - **`proton-vpn-cli`** — `protonvpn --help`. On Fedora it comes from Proton's
     official RPM repo, which the `bootc-fedora` image already configures.
   - **`proton-vpn-gtk-app`** — the settings escape hatch. Must be installed and
     **must not** be resident; confirm no autostart entry and that
     `connect_at_app_startup` / `start_app_minimized` are off.
   - **`nmcli`** (NetworkManager) — the authoritative connection cross-check.
   - **`gh`** — for issues on `robwilkerson/dms-protonvpn`.

   No QML toolchain is needed beyond what DMS ships.

3. **Integrations** — one integration needs user-specific setup:

   ### Proton VPN account (https://account.proton.me)

   Used for: everything. The plugin drives an already-signed-in CLI session.

   **Setup:**
   1. Run `protonvpn signin` and follow the prompts. Credentials are stored by
      Proton under `~/.config/Proton/`; this repo holds no secrets and needs no
      environment variables.
   2. Confirm with `protonvpn info` — it prints the account email, which is the
      popout subtitle.
   3. Quit the GTK app first if it's running; the CLI refuses while it's alive
      (and exits 0 doing so).

4. **Verify setup** — Symlink the repo in, reload, and confirm it appears:

   ```sh
   ln -s "$PWD" ~/.config/DankMaterialShell/plugins/protonVpn
   dms ipc call plugins reload
   dms ipc call plugins list
   ```

   Then confirm CLI and NetworkManager agree: `protonvpn status` against
   `nmcli con show --active`.

5. **Save onboarding record** — Write a summary to user-project memory at
   `~/.claude/memory/projects/-Development-lookout-software-dms-protonvpn/`:
   date, prerequisite status, whether the Proton session is signed in, and
   anything deferred.

## Argument Handling

- No arguments: run the full flow
- `status`: report current state without changing anything
- `refresh`: re-check every step and prompt for whatever is incomplete
